## 1. What changed this session
- **P4.4 (#48, PR #49) — native headless-peer harness (`src/peer/headlessPeer.ts`), the first real consumer of the P4.3 propose/commit seam.** `createHeadlessPeer` is a Node/Electron-capable peer that holds the shared `Y.Doc`, connects over the peer protocol (`HocuspocusProvider`), observes `Y.Text` deltas + awareness, and writes back through **propose/commit** — it *submits proposals and never self-applies*. This is the same peer model P4.5's external STARfolio interviewer and P6's native agent both wrap; the protocol stays Scroll-owned and consumer-blind (an instance is a peer, not a first-class concept).
  - **Never self-applies, by construction.** `propose(mutate)` clones the doc into a throwaway fork, runs the mutation on the fork, and proposes only `encodeStateAsUpdate(fork, before)` — the shared doc is a pure read. A refusal costs nothing (nothing was applied); a commit arrives back through normal sync like any remote update. Low-level `proposeUpdate(update)` is also exposed.
  - **Op-grain results correlate by proposal id** (`${doc.clientID}:${seq}`) through a `pending` Map, never by arrival order; foreign/unknown stateless frames are ignored (`parseProposalResult` → `pending.get` miss → no-op); a proposal bounded-times-out if no result lands.
  - **Observation surface:** `snapshot()`, `observeText(cb)` (observeDeep on `blocks(doc)`, handlers owned so `destroy` releases forgotten ones), `cameras()`/`observeCameras()`/`lookAt()` over `createPresence` on `provider.awareness`.
  - **Lifecycle:** idempotent `destroy()` settles every in-flight proposal (`'peer destroyed'`), settles `whenReady`, releases observers, tears down presence/provider, and closes the socket only when the peer *owns* it. `whenReady` gates on `synced` (⇒ authenticated, since Hocuspocus runs onAuthenticate before sync).

## 2. Decisions made and why
- **Socket ownership drives `preserveConnection`.** An injected socket (a caller sharing one transport across peers/rooms) is left alone on `destroy` (`preserveConnection: ownedSocket === null` → true when injected); an owned socket is torn down. Without this, destroying one peer would force-disconnect a sibling's shared socket (adjudicator-confirmed fix I3-F1, test-covered).
- **`destroy` settles `whenReady`.** The promise had only a resolve path; a peer destroyed before it ever synced would hang any `await peer.whenReady`. `destroy` now calls the captured resolver (fix I3-F2, test awaits whenReady post-destroy).
- **The one-shot `whenReady` send-gate is correct — a proposal during a reconnect is NOT dropped.** Inspector flagged it BLOCKING; refuted at provider source and confirmed by the adjudicator: `HocuspocusProvider.send()` bails only on `!isConnected`, which `onClose` (transient drop) never sets — only `disconnect()` does. So a mid-reconnect frame is queued at the ws layer and flushed on reopen. First send defers to sync; later sends fire immediately and the provider queues if needed.
- **`sinkSocketError` on teardown.** Tearing down a socket that never finished connecting makes `ws` emit a deferred `'error'` after Hocuspocus drops its own listener → unhandled 'error' crashes Node. `destroy` attaches a no-op error sink to the owned raw socket first. (Reaches a provider internal via cast — see carry-forward.)
