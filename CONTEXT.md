## 2. Decisions made and why
- **Pure `UPDATE`, not upsert, for the fenced snapshot write.** An `INSERT ... ON CONFLICT DO UPDATE ... WHERE owner_epoch` only evaluates the predicate when a row already exists — on the fresh-row path Postgres runs the plain INSERT unconditionally, `rowCount=1`, and the fence is silently skipped (adjudicator finding F-01). A pure UPDATE matches 0 rows when the row is missing **or** the epoch is stale, so `compact()` is self-fencing rather than relying on caller discipline (the row always pre-exists anyway: `acquireLease`/`appendUpdate` create it, and compaction only runs for a loaded doc).
- **Contain the fence throw in the ingress hook (F-02).** "Fail loud" must mean a contained, logged, per-doc failure — not process death. Hocuspocus fires `onStoreDocument` on an un-awaited `setTimeout` debounce (and un-awaited `executeNow()` in `onClose`), and the repo has no `unhandledRejection` handler, so a raw throw there would take down every room the instant the fence first fires in a real multi-owner deploy. The store still throws (tested); the extension catches, logs `[scroll-persistence] compaction rejected`, and re-defers seqs.
- **Fixed both latent findings now rather than deferring**, even though the adjudicator ruled PASS with zero blocking (both are latent behind the deferred multi-owner actor). They're cheap and each undercut the deliverable's own claim — a `compact()` that only fences when a row happens to exist isn't "the store enforces it," and a fence that crashes all rooms isn't "fail loud."
