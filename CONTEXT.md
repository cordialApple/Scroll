Rewritten to track exact applied seqs via an `onChange`-driven FIFO (`pendingSeqs`/`foldableSeqs` maps in `persistenceExtension.ts`) and delete by exact `seq = ANY(...)` list, never a numeric threshold. Verified by construction (adjudicator re-derived the happens-before chain from `@hocuspocus/server` source), not just by a green suite.
- **CI-only bug found and fixed post-merge-attempt** — Hocuspocus registers a process-wide SIGINT/SIGTERM/SIGQUIT handler on every `.listen()` and never removes it; GitHub Actions' own job teardown sent a real termination signal that fired every leaked handler from every test-created server in the process, each re-running `onDestroy` → `pool.end()` on an already-ended pool → hard crash. Fixed with an idempotency guard (`if (!pool.ended) await pool.end()`) in `server/hocuspocus.ts`. Never reproduced locally (no external signal sent to a local `vitest run`) — CI is now green with the guard.
- Fixed a genuine local flake unrelated to the above: running the full 22-file vitest suite in parallel against one shared local Postgres container intermittently timed out (2/5 runs) from real connection/resource contention. Added `fileParallelism: false` to `vite.config.ts`; 8/8 clean full-suite runs afterward.

## 2. Decisions made and why
- **Exact-seq-set compaction, not a MAX(seq) bound.** A numeric threshold can't distinguish "committed to Postgres" from "applied to the in-memory doc," and those two events are genuinely concurrent (separate async chains). Tracking every individually-confirmed-applied seq (via `onChange`, which fires exactly when `apply()` lands) and deleting only that exact set closes the race entirely, at the cost of one in-memory map per live document.
- **`fileParallelism: false` for the whole vitest suite**, not just the new persistence tests — the contention is against one shared `DATABASE_URL`, matching CI's single `services: postgres` container; serializing is cheap (suite is ~10s) and removes a whole class of cross-file DB races (schema bootstrap, connection pool exhaustion, ephemeral-port reuse) at once rather than patching each symptom.
- **Gate:** 4 parallel `inspector` agents (ordering guarantee / store correctness / CI wiring / test hygiene) → `adjudicator` → first pass **FAILED** (3 blocking: compaction race, weak ingress-timing assertion, no sabotage negative-control) → fixes applied, including an actual sabotage-then-revert (write-behind reintroduced, confirmed the tightened ingress test goes RED, reverted clean) → re-adjudicated **PASS**. One non-blocking warning carried forward (see §4).
