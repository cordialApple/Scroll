## 2. Decisions made and why
- **Close code 4400, not 4403.** The whole "refuse-and-resync" contract rests on the refused peer reconnecting. Read the installed provider: `onClose` special-cases exactly 4401 (Unauthorized) + 1009 (MessageTooBig) → `shouldConnect=false` (peer dies), and 4403 (Forbidden) → a quiet-gated early `return` that skips reconnect under the default `quiet:false`. Any other 4xxx falls through to `if (shouldConnect) connect()`. So 4403 (the first cut) silently broke the resync half — caught at the gate, fixed to 4400.
- **Validate the CRDT payload with `Y.applyUpdate` before persisting.** Envelope-only validation let a valid-envelope/garbage-payload frame through, which persistence appended (poisoning every future room load, since load replays the log through applyUpdate). Validating with the same op the load path uses, before the append, keeps un-decodable bytes out of the durable log. Costs one throwaway apply per sync frame — accepted at the trust boundary.
- **Durability tooth isolates the append log.** A memory snapshot would mask a broken append, so: huge debounce (no scheduled compaction) + a keeper connection awaited on `network.synced` (no 0-connection unload-compaction) ⇒ `documents.snapshot` stays null and reconstruction is from the log alone. A guarded sentinel keeps the doc from emptying to `[]` (which would make the equality vacuously true).
- **onAuthenticate flag-gated.** Defining the hook flips `requiresAuthentication` for the whole server; a tokenless provider would then hang. So the stub attaches only when a caller passes `authenticate()`, preserving every existing tokenless localhost test.
