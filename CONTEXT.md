## 2. Decisions made and why
- **stop = immediate cutoff, not "let the last utterance land"** (adjudicator ruling, grounded in `dictation.ts` comments: "only mutate while listening" / "leaving 'listening' discards any provisional tail"). This made the stop→onend window leak a bug, not an ambiguity — hence the adapter-level `intendedRunning` gate.
- **Two-layer [C1] guard on purpose.** The `dictation.ts` state-guard protects the post-`onend` window for every transcriber; the adapter `intendedRunning` gate closes the pre-`onend` window that state-based checks can't see. Neither substitutes for the other.
- **`finalizedCount` re-scans from index 0 with a monotonic-append-only assumption** about the native results list (fails safe: a hypothetical shrinking list drops a final, never double-inserts). `resultIndex` is on the event type but intentionally unused for now — see carry-forward [A1].
- **Mock-based unit tests, no jsdom.** The adapter takes an injectable ctor; the synchronous `MockRecognition` keeps CI deterministic. Real-recognizer async timing (stale-instance callbacks, restart storms) is explicitly P5.3's surface, where the adapter meets a real browser.
